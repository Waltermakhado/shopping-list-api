# Shopping List API

A small REST API for managing shopping list items. It uses Node.js, TypeScript, and Node's built-in `http` module; items are stored in memory and reset when the server restarts.

## Requirements

- Node.js
- npm

## Setup and run

Install the dependencies:

```sh
npm install
```

Start the development server with automatic restarts:

```sh
npm run dev
```

The API listens on `http://localhost:3000`. To compile the project, run `npm run build`. To run the compiled server, run `npm start`.

## Item model

Each item has the following shape:

```json
{
  "id": 1,
  "name": "Milk",
  "quantity": 2,
  "purchased": false
}
```

IDs are assigned by an incrementing counter and are not reused after deletion. A new item requires a non-empty `name` string and a positive integer `quantity`. The optional `purchased` field must be a boolean and defaults to `false`.

## Response format

Every response with a body is JSON. Successful responses use:

```json
{
  "success": true,
  "data": {}
}
```

Errors use:

```json
{
  "success": false,
  "error": "A description of the problem"
}
```

`DELETE /items/:id` returns `204 No Content` with no response body.

## Endpoints

### Create an item

`POST /items`

Request:

```http
POST /items HTTP/1.1
Host: localhost:3000
Content-Type: application/json

{
  "name": "Milk",
  "quantity": 2
}
```

Success response (`201 Created`):

```json
{
  "success": true,
  "data": {
    "id": 1,
    "name": "Milk",
    "quantity": 2,
    "purchased": false
  }
}
```

Returns `400 Bad Request` if the JSON is invalid, the body is not an object, the name is missing or empty, the quantity is not a positive integer, or `purchased` is present and not a boolean.

### Get all items

`GET /items`

Request:

```http
GET /items HTTP/1.1
Host: localhost:3000
```

Success response (`200 OK`):

```json
{
  "success": true,
  "data": [
    {
      "id": 1,
      "name": "Milk",
      "quantity": 2,
      "purchased": false
    }
  ]
}
```

An empty list is returned when there are no items.

### Get an item by ID

`GET /items/:id`

Example request:

```http
GET /items/1 HTTP/1.1
Host: localhost:3000
```

Success response (`200 OK`):

```json
{
  "success": true,
  "data": {
    "id": 1,
    "name": "Milk",
    "quantity": 2,
    "purchased": false
  }
}
```

Returns `400 Bad Request` when the ID is not a positive integer and `404 Not Found` when no item has that ID.

### Update an item

`PUT /items/:id`

Any subset of `name`, `quantity`, and `purchased` can be provided. Every provided field is validated.

Example request:

```http
PUT /items/1 HTTP/1.1
Host: localhost:3000
Content-Type: application/json

{
  "quantity": 3,
  "purchased": true
}
```

Success response (`200 OK`):

```json
{
  "success": true,
  "data": {
    "id": 1,
    "name": "Milk",
    "quantity": 3,
    "purchased": true
  }
}
```

Returns `400 Bad Request` for invalid JSON, a non-object body, no provided item fields, or an invalid field value. Returns `404 Not Found` when the item does not exist.

### Delete an item

`DELETE /items/:id`

Example request:

```http
DELETE /items/1 HTTP/1.1
Host: localhost:3000
```

Returns `204 No Content` with an empty body when the item is deleted. Returns `400 Bad Request` for an invalid ID and `404 Not Found` when the item does not exist.

## Status codes

| Status | Meaning |
| --- | --- |
| `200` | Request succeeded |
| `201` | Item created |
| `204` | Item deleted; no response body |
| `400` | Invalid JSON, ID, or request fields |
| `404` | Route or item not found |
| `405` | HTTP method is not supported for the route |
| `500` | Unexpected server error |

Unknown routes return `404`; unsupported methods return `405`. Unexpected server errors return a generic error message so internal details are not exposed.

## Manual Postman test checklist

Use `http://localhost:3000` as the base URL. Set the request body type to **raw / JSON** for requests that include a body.

- [ ] `GET /items` returns `200` and a JSON array.
- [ ] `POST /items` with `{"name":"Milk","quantity":2}` returns `201` and an item with `purchased: false`.
- [ ] `POST /items` with `{"name":"Bread","quantity":1,"purchased":true}` returns `201` and preserves `purchased: true`.
- [ ] `POST /items` with a missing name, empty name, invalid quantity, or non-boolean `purchased` returns `400` in the error format.
- [ ] `POST /items` with malformed JSON returns `400` in the error format.
- [ ] `GET /items/1` returns the matching item; `GET /items/0` returns `400`; and an unused positive ID returns `404`.
- [ ] `PUT /items/1` with `{"quantity":3}` returns `200` and leaves other fields unchanged.
- [ ] `PUT /items/1` with `{}` or an invalid field value returns `400`; updating an unused ID returns `404`.
- [ ] `DELETE /items/1` returns `204` with no body; requesting it again returns `404`.
- [ ] A request to an unknown route returns `404`; an unsupported method on a known route returns `405`.
